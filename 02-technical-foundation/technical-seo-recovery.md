# Technical SEO Recovery

## From SEO symptoms to technical priorities

Once the measurement foundation was in place, the next step was to improve the technical health of the website. The starting point was weak:

- Approximately 70% of the website was not indexed
- Duplicate pages existed
- Redirect and broken-page issues needed attention
- Page titles and meta descriptions were inconsistent
- Heading structures needed improvement
- Internal linking was weak
- URL structures were not always search-friendly
- Website performance was approximately 40

The objective was not to chase a perfect technical SEO score. The objective was to remove technical barriers that were limiting organic visibility and create a stronger foundation for future growth.

---

## 1. Cleaning up redirects and broken URLs

Redirects and broken pages were one of the first areas we addressed. These issues can create unnecessary friction for both users and search engines. Together with web development, we reviewed and improved:

- Broken URLs
- Incorrect redirects
- Outdated page destinations
- Links pointing toward pages that no longer existed

The principle was simple: **Important traffic and internal links should lead somewhere useful.**

Cleaning these paths helped create a more reliable website structure before we expanded the content strategy.

---

## 2. Reducing duplicate pages

The website also contained duplicate or overlapping pages. This created an unclear structure. If multiple pages serve almost the same purpose, it becomes harder to determine:

- Which page should rank
- Which page should receive internal links
- Where authority should accumulate
- Which page gives the user the best answer

We therefore reviewed overlapping content and reduced unnecessary duplication where possible. The goal was to move toward: **One clear search need → One strong primary page** rather than maintaining several weak pages competing for the same purpose.

---

## 3. Rebuilding page-level SEO foundations

We systematically improved the core SEO structure of important pages. This included:

### Page titles
Titles were rewritten to better connect the page with the relevant topic and search intent.

### Meta descriptions
Descriptions were improved to communicate the value of the page more clearly within search results.

### Heading structure
H1s and supporting headings were improved to create clearer page hierarchy. Instead of treating these elements as boxes to complete in WordPress, we connected them to the purpose of the page. For each important page, we asked:
+ What is this page actually trying to answer?
+ The page structure then needed to reinforce that answer.

---

## 4. Improving URL structure

URL structure was another part of the cleanup. URLs needed to become clearer and more consistent with the content and website architecture. Where relevant, we improved URLs so that they were:

- Clear
- Understandable
- Consistent
- Connected to the page topic
- Easier to manage within the wider site structure

Changing URLs was not treated as a cosmetic exercise. Where URLs changed, redirects also needed to be handled correctly to protect the existing user journey and organic value.

---

## 5. Strengthening internal linking
Internal linking became an important part of connecting the website. Previously, pages existed more independently. We wanted important pages to become part of a clearer structure. Internal links helped us connect:
**Supporting content → Relevant topic → Important landing page → Next step**

This had two purposes. For search engines, it created clearer relationships between pages. For users, it created more logical routes through the website. This became increasingly important as we started moving away from the website being an online flyer and toward a search-led acquisition platform.

---

## 6. Improving website performance
Technical performance was another major workstream. The website initially had a performance score of approximately: **40** Working together with web development, we focused on areas including:
- Image optimisation
- Code optimisation
- Caching

After the improvements, the performance score increased to approximately: **88**
This was a significant improvement in the technical foundation, but the score itself was not the business objective. The objective was a faster and more reliable website. A stronger technical experience supported:

- User experience
- Landing-page quality
- Organic performance
- Conversion
- Overall website health

The score was therefore treated as a diagnostic indicator rather than the final KPI.

---

## 7. WordPress implementation

The website operated on WordPress. The marketing team initiated and prioritised the SEO improvements. Some changes could be handled through content and website management, while more technical updates were implemented together with web development. The operating model was: 

**Marketing identifies opportunity** → **SEO impact is prioritised** → **Requirements are defined** → **Web development implements technical changes** → **Marketing validates the outcome** → **Performance is monitored**

This distinction was important. My role was not to personally write production code. My role was to make sure technical development effort was directed toward improvements that supported organic and commercial growth.

---

## What we deliberately did not claim
The technical work did not include every possible SEO intervention. During this phase, we had not yet made changes to:

- `robots.txt`
- Canonical implementation
- A new XML sitemap strategy

Those areas could be investigated as the SEO programme matured, but they were not part of the work described in this case. This repository separates what we actually implemented from what could theoretically be included in a technical SEO audit.

---

## The technical recovery model

The work can be summarised as:

**Measurement** → **Technical diagnosis** → **Broken paths & redirects** → **Duplicate content** → **Page structure** → **URLs** → **Internal linking** → **Performance** → **Stronger organic foundation**

Technical SEO was not the final growth strategy. It created the conditions in which the next stage of growth could work:

**Search intent + site architecture + better content.**
