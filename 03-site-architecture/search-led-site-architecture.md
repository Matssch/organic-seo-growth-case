# Search-Led Site Architecture

## From online flyer to acquisition platform

One of the biggest changes was not technical. It was structural. At the start of the project, the website mainly explained the company and its services. That made sense from an internal perspective, but it did not reflect how people actually search. There was no strong structure around vacancies and other high-intent search needs. The website therefore needed to move from:

**What do we want to tell people?**

toward:

**What is the user actually looking for?**

---

## The strategic shift
The old model was largely: **Company → Services → Information**
The new model became closer to: **Search need → Relevant page → Solution → Next step**

This changed how we thought about the website. A page was no longer useful simply because the company wanted to explain something. It needed a clear purpose within the user journey. For important pages, we increasingly asked:

1. What is the user searching for?
2. What problem or need sits behind that search?
3. Which page should answer it?
4. Is that page easy to discover?
5. Is the next step clear?

This became the basis for a more search-led website architecture.

---

## 1. Giving vacancies a stronger role

Vacancies were an important search opportunity. Previously, they were not positioned strongly enough within the website structure. That meant we were underusing one of the clearest areas of organic search demand. We increased the focus on vacancy-related pages and improved how these pages connected to the wider site. The goal was to create a stronger relationship between:

**Search demand** → **Relevant vacancy** → **Useful information** → **Application journey**

This made vacancies part of the acquisition strategy rather than simply content managed on the website.

---

## 2. Moving from company-focused to solution-focused content

The existing content often started with the organisation itself.It explained:

- Who we were
- What we did
- What services we offered

We started shifting the perspective. Instead of beginning with the company, we increasingly started with the user's need. 
The change was: **"This is what we do"**
to: **"This is the problem you are trying to solve, and this is how we can help."**

This had implications for:

- Page structure
- Headings
- Titles
- Content
- Calls to action
- Internal linking

The page needed to make sense both to the search engine and to the person arriving from search.

---

## 3. Building clearer page roles

We also became more deliberate about the role of each page. Important pages generally needed to support one of several purposes:

### Acquisition pages

Pages designed to attract users with a clear need or intent.

### Solution pages

Pages explaining how the company could solve a specific problem.

### Vacancy pages

Pages connecting search demand with available work opportunities.

### Supporting content

Pages that helped answer questions, create context and support the journey toward a more commercial or conversion-focused page.

This helped reduce the idea that every page had equal importance. Some pages existed to attract demand. Others existed to support conversion. Others existed mainly to provide trust or information. Understanding that role helped us structure the site more clearly.

---

## 4. Improving URLs and page hierarchy

The website structure also needed to become more understandable. We improved URL structures and page hierarchy where necessary so that important pages had clearer relationships with their topic and position within the site. This was supported through:

- Clearer page naming
- More logical URLs
- Better heading structures
- Stronger relationships between related pages

The objective was clarity. A user and a search engine should both be able to understand: What is this page about, and where does it belong?

---

## 5. Internal linking as part of the architecture

Internal linking became an important part of the new structure. Instead of allowing pages to sit independently, we increasingly connected related content. The model became:

**Supporting content** → **Relevant topic or solution** → **High-intent landing page or vacancy** → **Conversion**

This helped create clearer paths through the website. Internal linking therefore had two jobs:

### Search discovery
Help search engines find and understand important pages.

### User journey
Help visitors move naturally toward more relevant and higher-intent pages. This was especially important because the goal was not simply to increase page views. The goal was to turn organic traffic into useful journeys.

---

## 6. Search intent became part of website decisions
Search intent started influencing more than content creation. It also influenced how we prioritised the website itself. Instead of creating pages because they seemed useful internally, we increasingly considered:

- Is there a real user need?
- Is there search demand?
- What stage of the journey does this page support?
- Is there already another page serving the same purpose?
- What should happen after someone lands here?

This helped connect SEO more closely to website strategy.

---

## The architecture model
The shift can be summarised as:

### Before
**Company** → **What we do** → **General information** → **Hope the user finds what they need**

### After
**Search need** → **Relevant page** → **Clear solution** → **Connected content** → **Next step** → **Conversion**

The website became less of an online flyer and more of an acquisition platform.

---

## Why this mattered

Technical SEO made the website easier to discover, but site architecture made that discovery useful. The stronger organic growth came from connecting: **What people search for** 

with: **What the website provides**
and: **What the business wants the user to do next.**

That connection became one of the main foundations behind the increase from approximately: **2,000 → 6,500 monthly organic visitors within six months.**
